# 可组合无人机平台与 LOTF 混合梯度训练

日期：2026-09-26。依据：用户接受 Hydra 和组件组合，要求合并控制器、简化训练配置，
并将本次 LOTF 范围收敛到高保真前向、简化反向和 BPTT。
本文是本轮写入的实现规格；当前运行代码仍为 P1–P4 版本。

## 目标与交付

研究者选择任务、策略、控制器、动力学和训练配方，即可组合已有方法；新增论文按真正新增的
模块实现。共同交付是实际训练曲线、可加载策略、独立评测、完整回放和可复算结果，
模块是开发归属，不再增加四道用户逐次验收阶段。

本轮具体研究对象为 LOTF 的混合梯度训练子系统：高保真前向＋简化解析反向＋原生 BPTT。
状态悬停和八字跟踪使用作者任务、机型与配方；Crazyflie 和 P1–P4 历史实验继续保持自己的身份。
在线残差学习、滚动数据缓冲、运行时策略更新、ROS部署和视觉任务属于另立范围。
报告名称使用“LOTF 混合梯度训练子系统”，论文完整在线适应的5秒改善等结论属于原论文实验。

## 前向组件

| 用户配置组件 | 职责 | 组合规则 |
|---|---|---|
| 策略（含轨迹规划） | 根据目标、观测和内部状态输出轨迹或控制命令 | 神经网络、优化算法、固定轨迹生成都按输出契约使用；轨迹规划归于此模块 |
| 控制器 | 将策略输出转换成动力学接收的命令 | 内部可以串联轨迹跟踪、姿态/角速度环和混控；外部只选一个控制器预设 |
| 动力学 | 根据实际命令推进机体与电机状态 | 四种 Crazyflow 模型及 LOTF 模型分别保留原参数、单位与积分方式 |
| 场景 | 几何、障碍物、运动和外部作用 | 目标与成功条件归任务，场景提供可交互的世界 |
| 观测 | 传感器、状态估计、历史与可见信息 | 状态观测是现成预设；MID-360/图像在相应任务实现 |
| 任务 | 目标、门序、终止、时限和外部评价 | 同一场景可用于不同任务；奖励通过训练目标中的唯一奖励函数提供 |

“决策方法”“参考来源”不再作为两个一级组件。策略是总类，轨迹规划是其输出轨迹的实现类别。
固定八字、随机样条和读取轨迹文件放在轨迹规划模块的生成器实现中，保留“生成/读取/在线规划”的类型标记。
目标点和要求经过的门序属于任务输入。一个优化控制策略可以内部复用 MPC，其后的控制器只补齐尚需的命令转换。

### 控制器合并的实际例子

1. 固定样条策略 → 控制器预设（AttitudeMPC＋Crazyflow姿态内环）→ first_principles。
2. 姿态策略 → Crazyflow姿态内环预设 → first_principles。
3. 姿态策略 → 直通控制器 → so_rpy；姿态闭环响应已经包含在拟合模型中。
4. 角速度/推力策略 → LOTF Betaflight风格控制器 → LOTF电机与刚体动力学。
5. 电机转速策略 → 直通控制器 → 电机级动力学。

当前两种 MPC 的输出均为期望滚转/俯仰/偏航和总推力。MPC 的控制变量由具体优化问题确定，
其他实现可以输出角速度、力矩或电机命令；MPC这个名称不决定输出类型。
控制器包内部保留各环的状态和独立频率，外部配置只使用 `controller`。

### 必须明确的契约

- 每个输出声明类型、单位、坐标系、顺序、时间戳与有效时域。
- 控制器的入口类型匹配策略输出，出口类型匹配动力学输入；启动前检查。
- 动力学内部状态允许不同维度，通用记录读取统一物理视图；原生状态留给原生求解与微分。
- 飞控积分状态、暖启动、上次动作和延迟队列属于闭环状态，检查点与恢复一起保存。
- 常用时钟、积分器和单位转换由预设隐藏，所有实际生效值仍写入运行清单。
- 采样MPC和外部求解器可以前向执行；可微训练使用它们时须声明精确/隐式/代理导数能力。

## 四类训练配置

| 配置组 | 包含内容 |
|---|---|
| algorithm | PPO、APG/BPTT、SHAC及作者算法适配；优化器、学习率、采样/小批量更新和算法必需缓冲区作为内部参数 |
| network | 策略与可选价值网络、动作分布、记忆状态和归一化 |
| objective | 唯一奖励函数、终端价值系数、监督损失和约束惩罚；奖励由环境包装器调用，算法损失由训练器组合 |
| training | 交互预算、并行数、种子、评估/保存频率和恢复选项 |

任务、场景、观测和随机化复用前向环境，不复制一套“训练场景”。领域随机化放在 `env.randomization`，
适用于训练和评测。课程配置作为任务参数；有需要时算法内部拥有采样缓冲区。
“策略训练”统一称“训练”，只保留 train、evaluate、simulate、replay 四种运行方式。
批量实验由 Hydra multirun 展开；系统辨识与在线适应是将来可添加的独立运行方式。

## 动力学与梯度

代码归属继续区分控制器和动力学；训练求导对象是策略输出之后的完整状态转移。
`dynamics.forward` 选择前向物理；`dynamics.backward` 选择直接微分或具名代理梯度预设。
代理梯度实际包围控制器＋物理推进后的统一步进接口，能覆盖整个低层执行链。
具体配置同时记录反向状态投影和动作语义，避免把不同状态维度直接替换。

MPC 的 `controller.prediction` 选择内部预测模型；评测默认复用前向模型，需要迁移实验时
通过实验覆盖项选择另一前向配置。日常配置只显示实际需要改变的模型用途。

## Hydra 与代码组织

Hydra 负责配置组合和可信本地对象构造；一个实验预设包含完整依赖。
常用选择形如 `experiment=lotf_hybrid_hover`，复杂参数只在对应配置组中展开。
此命令形式为设计目标；实际入口完成测试之前不写入“当前可用命令”。

```text
src/drone_playground/
  composition.py                 构造、契约验证及纯函数步进组合
  policies/                      策略实现；planning/容纳轨迹生成与在线规划
  controllers/                   一个控制器模块，内部拥有跟踪、飞控和混控
  dynamics/                      模型适配、参数及gradients.py代理规则
  tasks/                         任务、场景、观测和领域随机化
  learning/                      算法、网络、训练目标和一个训练入口
  evaluation/                    统一冻结评测
  runs/                          现有记录、恢复和rscope导出
configs/
  experiment/                    一次选择完整论文配方
  policy/ controller/ dynamics/  前向链可替换配置
  task/ scene/ observation/      环境配置
  algorithm/ network/ objective/ training/
```

与现有代码迁移时，直接更新调用、配置、测试和当前文档，历史数据格式采用明确版本读取。
配置分组表示可改变的位置，不要求给每一个参数建立管理器或公共基类。
优先复用 Crazyflow、Brax、LOTF 的原生函数；新适配集中处理约定差异。

## LOTF 按模块实现

锁定上游 `uzh-rpg/learning_on_the_fly@cba6e5370773ace8a08107f02810eecabf16c793`。

| 所属模块 | 实现/来源 | 对外行为和验证 |
|---|---|---|
| 策略 | 上游 MLP及原始动作映射 | 使用原任务观测和推力/角速度顺序；相同参数输入对应相同动作 |
| 控制器 | Quadrotor._llc_betaflight | 保留低层频率、混控及油门到目标转速映射；与上游每子步输出对照 |
| 动力学前向 | Quadrotor._full_dyn及固定多项式气动修正 | 保留电机状态、积分和物理参数；多步状态与原生高保真step对照 |
| 动力学反向 | simplified_dyn及原custom_jvp语义 | 用p/R/v和推力/角速度构造导数；与简化模型导数对照，状态投影明确 |
| 算法 | lotf/algos/bptt.py | 保留确定性策略、展开窗口、损失缩放和原优化器配置；实际参数更新与上游对照 |
| 任务/观测/目标 | hovering_state_env、traj_tracking_state_env及对应Notebook | 原目标、初态、奖励、延迟、回合规则和参考轨迹；原机型与Crazyflie身份分开 |
| 评测/记录 | 复用现有框架 | 新进程加载策略、冻结统计、完整分母和rscope重放；输出学习曲线与误差表 |

逻辑上模块独立；具体复用可以保留上游 `Quadrotor.step` 作为组合预设内部的整体调用，
只要逐项声明内部控制器和物理模型，且不在外层重复执行控制器。真正替换其中一项时才抽取内部函数。

本次模块开关为高保真前向开启、学习残差前向关闭、简化反向开启、BPTT训练。
高保真代码自带的固定经验气动项属于原物理模型，按上游保留；它与在线拟合神经残差分别记录。
LOTF BPTT 作为同一 JAX/Flax/Optax 体系的具名作者适配，和 Brax APG 的不同配方保持各自名称。

## 训练结果与验收

共同实验交付覆盖状态悬停和八字跟踪。每个任务训练到配置声明的完整预算，保存初始、中期、最终和
开发集最佳策略，并在新进程独立评测。验收表包含回报曲线、位置/姿态误差、失败率、实际交互量、
编译/训练/评估耗时和回放；算法未达标如实保留，代码接入测试与训练质量分别判定。

配方以锁定上游Notebook为可执行来源，论文III-C/IV-A作为说明来源。论文状态任务的名义预算
为300轮×100环境×150步，即450万次交互；若Notebook具体值不同，运行前列出差异并固定其中一种。
第一轮训练种子0，开发32/留出128沿用项目评测组织；这是本项目评测协议。论文的8回合稳态误差
只有在任务、扰动、窗口和模型完全对齐的复评中才作同列数值比较，多训练种子仍由P6承担。

前向检查验证物理状态，反向检查验证代理导数；高保真有限差分与代理梯度之差属于设计定义。
切换到直接梯度才要求与同一前向的有限差分一致。继承P1–P4回归以固定输入输出、检查点重载和
回放读取为主，已有正式实验结果保持原始字节。

## 原论文在线部分的定位

LOTF 论文III-D与IV-A明确描述：记录近期状态和动作，构造实测加速度与解析预测的差，
训练残差网络，再交替更新策略。在线适应可作为已有模型/算法之上的调度器扩展，概念上兼容。
本轮选择聚焦可组合仿真和混合梯度训练，因此不纳入该调度器及残差训练任务。
