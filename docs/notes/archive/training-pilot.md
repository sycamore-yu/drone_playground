# 第一版开发集训练合同

用户于2026-09-29确认本轮先做开发集探索；遇到平台期或异常保留证据共同诊断。正式三种子和留出验收另按 [release-plan.md](release-plan.md) 执行。

每个学习方法先使用 seed=0，基线加最多两次调整，每次训练最多3600秒。研究不同任务时单独建立 study；首个 study 是 BPTT／FigureEight 跟踪。学习率允许在1e-5至1e-2之间调整，梯度裁剪在0.1至10之间；只在已有结果支持时更改，每次保留精确参数与理由。其他任务首次启动前写出实际配方。

已核查的网络和优化器来源见[配置映射](../research/learning-configs.md)。

BPTT／SHAC初始参考预算为1000次更新、32步时域。来源为 DiffAero 固定提交 `291ea14196aefbebcf7387dd71f7e096c83878b7` 的 `cfg/config_train.yaml`：上游并行1024；本机首轮并行128，实际预算为4,096,000个决策步。两者不能直接按更新次数比较采样效率。实际物理频率、子步、延迟、编译耗时、训练耗时和显存随运行记录；GPU为RTX4090，JAX显式使用CUDA。

首轮沿用项目已有物理环境、观测、奖励、网络和延迟。BPTT基线保留学习率0.005、裁剪1.0及原调度，只修改上述已声明预算。开发评测32回合，固定开发种子，每次9个参数快照。FigureEight当前只有一个场景族，32回合覆盖开发初态；不能据此声称覆盖随机轨迹。导航按“难度／场景类型”分组。

标量目标为最大化最差场景组的成功率。跟踪只有完成且单回合位置RMSE≤0.25m才记为成功；竞速要求完成全部任务；导航要求到达。失败保留在分母，目标并列时保留最早达到该值的快照。误差、门数、碰撞和耗时保留作诊断，不暗中改变优化目标。配置为 `training=release_pilot`，选择规则为 `release-pilot-v1`。

PPO跟踪基线沿用学习率0.0008、1024并行、16步展开和2,097,152步预算；SHAC沿用actor/critic学习率0.003/0.002，其余采用上述128并行、1000×32预算。竞速先沿用各方法跟踪基线参数，单独建study。

optim-agent使用本地技能包构建的0.2.0 wheel（PyPI镜像只提供0.1.x，未混装），SHA256为 `7ebd9d0c097a43ec489d7003026de30f67dd83c6f5be0a0060b3bcc04df413c8`，保存在忽略的 `tmp/optim-agent-package/`。每次运行的launch.json重复记录其摘要。使用顺序ask/tell；study与启动清单保存在忽略的 `.optim-agent-runs/`，训练、权重、曲线和逐回合结果放 `experiments/`。每次启动前记录源码差异、配置、命令、输出目录；恢复先检查已有运行，避免重复训练。异常记failed，主动提前结束记pruned并保留最近真实中间值。开发成功不自动触发发布或等同18格验收。

导航留出范围已由用户确认：第一版采用固定 Navigation8 与独立冻结的初态／扰动种子；训练／开发／留出应记录各自种子、分布和实际生效字段。固定几何的重复不是未见几何泛化，逐场景报告不得混淆这两种结论。不能仅重复同一个确定性回合来充作独立样本。

SHAC竞速t0（actor lr=0.003，1000次）在所有9个快照均0/32通过，750次快照仍在约0.6–0.8s非碰撞失败，不能把其低RMSE视作成功。t1只将actor学习率降到0.001，其余预算与开发样本不变，检查critic引导下大梯度导致的早期飞行不稳定；baseline结果及源码保持不变。

深度导航t0使用独立CNN／GRU适配、D435i样式10m深度、AdamW学习率0.001、8并行×32步×1000次（256000决策步），Navigation8每场景1个开发回合、目标4m/s，9次快照、60分钟上限。该初始开发预算不等于DiffAero的1024并行预算，也不是上游深度论文的50000次完整预算。

SHAC竞速t1仍全部快照0/32。预算内最后一次t2采用DiffAero源码启发的独立配方：`algorithm=shac_diffaero_adapter network=diffaero_mlp`，actor/critic学习率0.001/0.003，宽度[256,128]，actor Adam β=(0.9,0.999)，固定学习率，目标critic旧参数权重0.995（对应上游新参数0.005）。这是多参数配方比较，不作为单变量因果消融。仍保持1000×128×32、相同32开发回合；本实现仍为确定性actor、Brax初始化、无LayerNorm的V critic和全批8次critic更新，不冒充上游的随机actor、熵正则和8个minibatch更新。

t2实际配置审计：Hydra的method._self_覆盖了training组中的并行数和更新数，实际为64并行×32步×320次=655360步，未执行宣称的128×1000。原始启动意图和源码不改写，真实配置及偏差登记保存在对应运行的`configuration-deviation.json`；第320次更新32/32开发回合通过。该候选在预算上限之内，但不能用于声称与t0/t1相同交互量的比较。后续独立种子冻结实际64×320配置，并在启动前审计解析结果，不增加第4个调参候选。

点云导航新t0从随机初始化开始，独立于已结束的45000次来源状态：原PointNet／GRU网络，AdamW lr=0.0001，8并行×32×1000、9次快照、每场景1个开发回合、目标4m/s、60分钟上限，实际256000决策步。启动前对Hydra解析配置进行预算断言。与冻结控制确认共享GPU，因此记录的墙钟不能作为独占GPU下的算法效率比较。

点云t0的9个快照均0/8到达，后期主要碰撞和越界（非数值异常），559秒完成1000更新。t1只将AdamW学习率从0.0001提高到0.001，仍为8×32×1000和相同开发种子，检查原论文学习率在短预算下的优化进度；原配方、权重和失败回放保持独立。

PPO竞速t0的确认seed=1在2,097,152步内仍未完成，开发快照的过门数从0增加到2；三个种子的原确认结果保留。该study目前仅使用t0，仍有两次已批准调整额度。t1固定seed=0、学习率0.0008、1024并行、16步展开、9次开发快照与原目标，只将交互预算增至4,194,304步，仍受60分钟训练上限约束。目的为检查更充分优化后的配方；单个seed=0开发满分不能证明多种子稳定，候选须另做独立确认，旧失败结果不改写。

## 第二阶段（2026-09-30批准）

点云从零独立训练，不使用45000次参数热启动。导航开发固定Navigation8，每场景8个初态／扰动，共64回合；种子50000–50063，分布沿用navigation8-initial-v1，姿态、位置、速度和25–50ms传输延迟实际生效。先复核已有从零训练快照，保留旧选模与旧正式结果，不覆盖其身份。

新规则navigation-development-v2按最差场景成功数、总体成功数排序，精确并列保留最早更新。optim-agent标量为(65×最差场景到达数＋总到达数)/584；它是保序目标，不能标为成功率，同时报告真实最差／总体成功率。每个场景8回合，一次最差场景改善优先于总体64次变化。

深度和点云各最多追加2个候选，每次训练墙钟上限3600秒。SHAC竞速最多追加2个候选，每次3600秒；首候选核实实际128环境×32步×1000更新，沿用DiffAero启发网络及优化器，使用原失败seed2作为开发诊断种子；第二候选根据结果决定是否降低学习率。原有试验历史不改写。

候选确定后，确认使用新的独立训练种子30、31、32，留出种子60000起；导航各训练种子固定策略评测25次/场景（共200、静态与动态各100），SHAC竞速各100。不得用留出结果重新选配方。无预训练、随机状态或优化器复用。EGO已由用户接受交付，退出本阶段调试，原质量豁免单列。


第二阶段旧快照只读复核完成45次（2880个开发回合）：深度seed0／1／2的新选择分别为750／1000／625次，最差场景4/8、1/8、0/8，总到达60/64、53/64、49/64；两个从零点云配方所有快照仍0/64。旧选择及正式结果保持原样，来源、参数和实际初态核验见[复核凭据](../../../artifacts/verification/navigation-development-review.json)。

首批新候选：SHAC使用原失败seed2、实际128×32×1000，保留DiffAero启发的actor lr .001／critic .003；点云使用seed0、8×32×1000、lr .001，只将point_input_scale设为.1，检验已有输入尺度诊断；深度使用seed0、32×32×1000、lr .001，以更大批量提高采样覆盖。三者均为空warm_start／resume，单独排队使用GPU；已在启动前断言实际解析配置。导航新选模带64个初态扰动，不能直接把它的标量目标与旧8回合目标比较。

新源码选模与现有初态合同的15项针对性测试通过，lint通过；固定源码为927f8a7。第二候选须依据本方法首候选的真实结果再选择，不预先自动搜索。

首批从零点云候选的准确入口（后续候选和确认使用独立run_id／seed）：

```bash
JAX_PLATFORMS=cuda pixi run train experiment=papers/pointcloud_diffsim \
  env=navigation/recurrent_acceleration algorithm=recurrent_navigation_bptt \
  training=navigation_recurrent evaluation=navigation_v2 training.num_envs=8 \
  training.policy_updates=1000 training.num_evals=9 training.seed=0 \
  training.checkpoint_eval_episodes=8 training.checkpoint_eval_metric=navigation-checkpoint_eval-v2 \
  training.max_wall_seconds=3600 training.warm_start=null training.resume=null \
  algorithm.horizon_length=32 algorithm.learning_rate=0.001 \
  +network.point_input_scale=0.1 runtime.device=gpu run_id=<独立标识>
```

方法预设中的_self_可能覆盖training组，故并行数、更新数、checkpoint_eval回合及选模规则必须显式给出；启动器会先解析并断言，而不是只登记意图预算。
