# P3 随机样条 PPO / 拖曳模型的数值故障

原运行 v1 与降低学习率后的 v2 均在下一次保存策略前触发非有限参数检查。
v1/v2 的完整日志和最后有限检查点保持原样；降低学习率没有解决故障。

## 定位证据

临时诊断在原生 Brax 的梯度计算之后检查第一次非有限梯度，通过 JAX 调试回调保存
输入、损失与梯度。安装包文件没有改动。输入数据位于
`tmp/p3p4/ppo-nan-diagnosis/first-bad.pkl`，结构化统计归档于
[首次异常统计](p3-numerical-diagnosis.json)。

此时策略/价值网络权重全部有限，采样累计数为835584；出现异常的是一个物理观测：
位置仍在任务边界内，速度约数米每秒，角速度某分量达到8.119113043114375e26。
此前该回合的俯仰角达到-89.34度，接近拟合RPY动力学的欧拉角奇异区域。
该状态每个标量仍为有限数，原有 isfinite 检查放行；随后观测二阶矩与价值损失溢出，
价值网络梯度出现无穷大，参数更新变为非有限值。日志中的GPU编译警告并非已定位的直接原因。

## 具名修正

新配置 `random_ppo_drag_v3.json` 恢复原始学习率0.0008、相同4194304次交互预算，
显式启用 `finite-square-v1` 数值有效性边界：观测各项及平方和均须在原浮点类型中可表示。
数值发散的步记为失败、回报-1，终端记录使用上一步有效物理状态，随后按既有随机数协议重置。
普通有效步逐元素保持原行为，不剪裁正常观测、不放宽成功规则、不修改物理模型或Brax优化器。

该边界为配置开关，旧实验保持原协议。v3 的任务标识包含 `+finite-square-v1`，
结果表保留v1/v2失败来源及此修正，不能把全部单元描述成完全相同的数值处理。
`tests/test_numerical_boundary.py` 覆盖捕获到的有限溢出观测、20步普通行为完全一致、
真实发散动力学的一步失败/有限末状态/随机新回合。三个测试均先失败，再通过。
