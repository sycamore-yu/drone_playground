# 深度可微飞行的当前实现边界

来源为《Learning vision-based agile flight via differentiable physics》，DOI [10.1038/s42256-025-01048-0](https://doi.org/10.1038/s42256-025-01048-0)。已在外部参考目录固定并用GitNexus索引 [DiffPhysDrone](https://github.com/HenryHuYu/DiffPhysDrone/tree/271936190b5c2a5e760230e718fa6b167718a5bf)。参考仓库当前未找到许可证文件，本项目没有复制其源码；新的网络和传感器为独立JAX实现。

可执行入口为 `method=learning/depth_navigation`，结果身份是 `depth-flight-navigation-adaptation-v1`。它将深度输入、CNN／GRU、加速度与速度预测双头接入现有导航的物理模型、目标和评测循环，适合共同条件的模块研究。它不是已完成的上游CUDA全配方复现，也尚无收敛声明。

| 部分 | 当前适配 | 与固定上游源码的关系 |
|---|---|---|
| 深度 | 64×48、D435i标称视场87°×58°、0.2–10m轴向深度、相机上倾20° | 用户指定10m量程的共同条件适配；不是上游相机或真实双目噪声复现 |
| 预处理 | `3 / clip(depth,0.3,10) - 0.6`，4×4最大池化至12×16 | 保留近物体响应与空间布局；未知像素按远量程处理 |
| 网络 | 32／64／128卷积、192维投影与GRU、6维输出 | 独立Flax实现；初始化与PyTorch权重格式不宣称等价 |
| 状态 | 机体系速度／目标速度、姿态世界竖直行、余量标量 | 10维；当前余量取共同模型的机体半径，不使用上游随机余量 |
| 命令 | 机体系加速度头减去速度预测头，再转世界系净加速度 | 速度反馈增益为1/s；当前不加入推力估计扰动 |
| 辅助损失 | 速度预测与停止梯度的真实机体系速度间MSE | 与导航目标共同训练两个头 |
| 环境 | Navigation8、10Hz策略／500Hz共同PointMassLag、25–50ms延迟 | 这是共同导航适配；上游15Hz带抖动控制、阻力、风、姿态滞后和选择性反传尚未完整移植 |
| 主损失 | 当前共用导航速度／进度／净空／加速度／jerk目标 | 不能冒充上游30步速度平滑、障碍接近权重等完整损失 |

当前有输入尺度、循环记忆、梯度有限性和真实几何短程rollout检查。首轮训练沿用户同意的开发预算运行；上游 `main_cuda.py` 默认50000次、batch64、horizon150与DiffAero的1000次预算属于不同实验，不混写为同一个来源。

下一项原配方复现工作应独立加入其动力学、姿态更新、噪声／风随机化与完整损失，并以固定输入逐步数值对照验证。届时保留当前共同条件适配的身份与结果，不覆盖历史运行。

## D435i参数与MuJoCo来源

按用户确认，当前深度导航适配使用10m截止量程；超过量程和近于0.2m的返回均标为无效，输入值填10m，同时保留有效位。网络的远量程从 `env.sensor.far_m` 读取，传感器与预处理不会分别固定成10m和24m。0.3m是逆深度预处理的下限，不是传感器近裁剪。

已在 `reference_repos/mujoco_menagerie` 稀疏检出并GitNexus索引提交 `2cd6b7be15440787d12f7eb4c34ae1a1a03237c4`。[D435i XML](https://github.com/google-deepmind/mujoco_menagerie/blob/2cd6b7be15440787d12f7eb4c34ae1a1a03237c4/realsense_d435i/d435i.xml)只有外形、碰撞和0.072kg外壳质量，没有camera或深度传感器定义；不能把该模型当成现成的D435i测距仿真。[官方规格](https://www.realsenseai.com/products/depth-camera-d435i/)给出深度视场87°×58°；10m是本实验选择的最大可见深度，不代表硬件在10m内均有相同准确度。

相机直接在64×48策略网格渲染轴向深度，保留两个方向的完整视场，因此fx与fy不同；不是先渲染HD图再做图像插值。选用30Hz名义采集模式、每三帧消费一次，实际只计算10Hz被消费帧，与导航策略同频。日志同时记录这两个频率、内参、无效值和重采样定义。虚拟相机放在机体原点，上倾20°是本配方的安装角，与D435i内参无关；未加入外壳质量、IMU、双目遮挡、失配或距离相关噪声。

现有 `sensor=d435` 是保留SANDO来源的120×90、85.2°水平视场、0.1–10m配方，历史及当前EGO原配方均使用它。它与当前深度网络的D435i参数适配分别命名；受控组件比较时须统一实际传感配置，不把两者默认为同条件。

## 固定几何的独立扰动检查

首版正式导航将使用 `evaluation=navigation_release evaluation.episodes=25`：每个Navigation8场景25个独立初态，共静态100＋动态100回合。显式写出`evaluation.episodes=25`，避免方法自身的开发默认值覆盖评测组。候选策略先在开发种子上做同分布检查，不用留出结果选超参数。

分布为起点附近xyz分别±(0.25,0.25,0.1)m、速度各轴±0.1m/s、航向±5°，另保留已有25–50ms传输延迟。每例使用独立PCG64子流，候选位置须在世界界内且机体净空≥0.15m；无法采到合法点则报错，不悄悄回退同一起点。报告保存实际位置、速度、姿态、种子、净空、拒绝数和延迟物理tick。几何保持固定，不声称未见几何泛化。

深度与点云共享这一重置采样器；当前已接入这两类导航评测，原生EGO／SUPER的相同扰动接线仍待完成。每种方法的完整3种子验收和不同实际动力学间的组件对照仍须分别报告。

2026-09-29的独立开发检查 `depth-navigation-initial-perturb-dev-20260929` 使用第875次候选和上述初态分布，8/8到达。后续深度确认使用训练种子0、1、2：保持原8×32×1000训练配方和原开发选模，留出种子30000–30199，每场景25例。每个种子的静态／动态各100例分别要求≥90%，逐场景另外报告；源码与完整清单在独立冻结工作树记录。改变配方将另起结果身份，不使用这些留出结果调参。
