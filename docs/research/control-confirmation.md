# 第一版学习控制的冻结确认阶段

本阶段只覆盖 PPO／SHAC／BPTT × 跟踪／竞速六格，不能代替完整18格。六组seed=0都已有开发候选；确认阶段不搜索新超参数。

## 冻结条件

- 任务、场景、观测、控制器、实际动力学、目标轨迹、奖励及动作扰动全部从相应候选检查点的完整解析配置继承。训练种子为0、1、2；seed=0保留原有候选及源码凭据，另外两个种子从随机初始化重新训练。
- 跟踪为50Hz、10秒FigureEight、`so_rpy`／`cf2x_L250`；竞速为50Hz原配置LSY课程及对应机型。各组显式解析25–50ms动作延迟。赛道划分、动作／动力学扰动由已固定源码及场景文件确定，不能在看到留出结果后修改。
- BPTT跟踪／竞速和SHAC跟踪为128并行×32步×1000更新。PPO两组为1024并行×16步、2,097,152决策步。SHAC竞速为已核实的DiffAero启发配方、64并行×32步×320更新；名义启动预算偏差另见[开发合同](../training-pilot.md)。每次上限3600秒。
- 各次训练使用相同32个开发种子（20000起）和9个快照，按`release-pilot-v1`选择最差场景成功率最高的快照，并列选最早。不同训练种子分别选模，不只保留表现最好的种子。
- 每个冻结策略运行100个留出回合（30000–30099），沿用任务原有留出划分和已生效随机扰动；不声称覆盖未登记的随机轨迹／赛道分布。跟踪每个种子完成率≥95%、完成回合平均位置RMSE≤0.25m；竞速每个种子完成率≥90%。失败保留在100回合分母；全部回合的有效轨迹RMSE另外报告。
- 这是组件控制配方的确认，不是DiffAero／VisFly的原方法复现，也不是等交互预算下的算法排名。导航的初态／扰动合同另外冻结，尚未进入这一阶段。

## 运行和证据

正式任务由固定提交的独立工作树执行，避免主目录后续接口开发改变训练源码。`scripts/tools/confirm_control_learning.py`读取冻结JSON清单，保存每项完整解析配置及SHA256，在独立子进程中顺序训练和评测。每个job都有日志、权重、曲线和逐回合结果。程序支持已完成job跳过，但遇到未完成同名运行会停止，要求先核查原因。

`evaluation/release_control.py`单独计算首版质量门槛，拒绝开发集、未冻结参数、少于100回合、丢失回合或重复评测种子。它保留历史评测中的原始字段；新的`eval/release-validation.json`使用95%跟踪门槛，不沿用历史90%判据。逐种子通过后该格才通过。

清单、工作树提交和进度都保存在对应 `experiments/release-control-confirmation-20260929/` 下；源码工作树为只读运行证据，不作为第二个开发仓库。训练异常保留诊断，不自动扩展调参次数。尚未完成的组保持未验收状态。
