# 原生控制与导航的首版确认

原生算法没有训练种子要求，仍须固定源码、运行库、配置和评测条件，每任务至少100个独立留出回合。ROS规划器由共同gRPC服务接入；独立C++模块不要求参加可微训练链。

## AttitudeMPC／SamplingMPC

先以32个开发种子（20000–20031）检查完整跟踪／竞速；候选配置冻结后用30000–30099正式评测。组件条件采用与学习控制相同的25–50ms动作延迟，逐回合记录实际延迟；原默认零附加延迟结果保留作独立原配方诊断。模型、控制频率和轨迹都继承开发候选，禁止用留出结果选配置。

`scripts/tools/confirm_control_solvers.py`从固定源码工作树读取清单，核验开发报告摘要、环境、控制器和运行配置，再启动独立子进程。`evaluation=control_release`启用首版门槛：跟踪完成率≥95%、完成回合均值RMSE≤0.25m；竞速完成率≥90%。失败保留在分母。

报告中的`parameter_identity_kind`明确为求解器配置，不伪称神经权重。报告记录实际acados库及控制适配源码摘要；私有生成代码保存在每次运行目录。SamplingMPC的并行预测使用GPU，宿主物理与acados仍使用CPU。共用GPU和CPU时的耗时只作为运行记录，不用于宣称独占性能。

AttitudeMPC跟踪已修正末尾参考不足：周期任务继续其定义的周期，有限轨迹末端保持，预测时域延伸到最后一次任务决策之后。不能因缺少预测参考把10秒任务提前在9.5秒结束。

竞速延迟诊断保留相同RandomActionDelay包装及随机数分裂：四个开发种子在零附加延迟下4/4完成，RMSE 0.06738m；固定38ms预测器只读取原MPC模型、当前状态和历史已发命令，在实际25–50ms延迟下4/4完成，RMSE 0.05673m。该预测器为单独标识的适配原型，32回合开发检查已完成32/32、RMSE 0.05545m，未出现非零求解器状态；不计入原版或正式质量结果。

SamplingMPC竞速100回合确认期间，并发负载导致预计评测时间超过共用训练运行器的3900秒看门狗。已终止单独的等待协调器，原评测子进程、配置、种子和累积结果继续运行；接管身份及原因保存在该批次`evaluation-watchdog-handoff.json`。新监督器观察原进程并在其完成后运行同一冻结验证器，没有重训或重置回合。评测耗时不能用作独占运行性能。

## SUPER／EGO

`evaluation=native_navigation_release`把`evaluation.episodes`解释为**每场景重复次数**：静态S01/S02/S03/S06或动态D01/D02/D03/D06各25次，共100回合。必须显式给出`evaluation.episodes=25`，避免方法默认值覆盖评测组。既有按难度重复的历史入口保持原义。

初态分布与深度／点云验收共用`navigation8-initial-v1`。同一场景、同一次重复使用相同PCG64种子语义；静态和动态分开运行仍对应八场景交错编号。采样位置、速度、航向实际进入动力学、首帧传感和进度原点；场景几何固定，不宣称新几何泛化。每个回合的种子和实际初态保存在报告中。

轨迹归档和回放使用实际场景编号；不能再根据三个难度的等分切片猜测场景。正式验收要求四个场景完整出现、100个独立初态、到达率≥90%，并逐场景报告成功率。每个ROS实例须记录一致的原生二进制身份，无原生动作的到达不算算法成功。

规划速度由算法在`method.limits.max_velocity_mps`上限内选择，原配方仍为20m/s上限；不读取学习方法的`commanded_speed`作为目标。4m/s上限的EGO诊断独立登记，不能冒充20m/s协议结果。原生与点质量学习适配的实际动力学、传感器和执行器不同，不能将这两类确认表直接当成固定所有条件的算法排名。

开发检查可设置`evaluation.split=dev evaluation.episodes=1 evaluation.release_validation=null`，覆盖该任务全部四场景。小样本开发结果不替代正式100回合证据。

后续确认运行已分开监督时限：训练仍为3900秒（含收尾余量），冻结评测为14400秒；实际监督时限单列于任务JSON，不改变策略／求解器配置摘要或逐次求解预算。

SUPER静态首个正式批次在29个回合后因ROS订阅启动超时失败；四路独立启动探针随后均约21秒就绪，未复现故障，不能据此认定原因已修复。原批次完整的easy归档和逐回合诊断保留，medium的四条内存轨迹不能补称已归档。现役评测器新增每回合原子记录与完整／中断轨迹保存，即使后续进程失败也保留前面的独立记录；服务异常标为执行未完成，不重写为碰撞或到达，正式批次仍须完整通过验证。该改动不追溯改变已运行批次。

`method=optimization/attitude_mpc method.decision.delay_compensation_ms=38`可显式启用上述执行适配。默认0保留原配方；每个回合清空历史，预测初态使用已观测状态，预测期间只使用此前发出的姿态／推力命令，参考同步前移38ms。积分步长为2ms，全部预测成本计入决策耗时，报告另记`execution_adaptation`和预测器源码摘要。当前适配支持固定任务参考；实时外部Trajectory模式不能直接启用，须先补齐回退命令历史与未来时域协议。9项针对性检查已通过，包括命令实际生效时间、重置、姿态／角速度变换和真实acados求解；随后以正式代码重新验证开发集，再冻结留出配置。
