# 决策方法、执行状态转移与任务协议

日期：2026-09-28。状态：设计方向已采纳；配置与代码迁移待讨论定稿。

## 用户决定与范围

用户同意学习与优化混合方法作为一类决策实现，同意 AttitudeMPC、SamplingMPC 的平台配置
归入决策方法，执行控制器承担后续跟踪、飞控内环和混控。用户采纳三流水线临时评审的
候选 1（决策方法）、2（执行状态转移）、4（任务协议与模块能力分开校验）。
破坏性配置迁移在领域关系讨论清楚后开展。本轮交付领域术语、决定与架构说明。

## 原因与决定

当前 `policy` 包含神经策略和 EGO/SUPER，`controller` 同时包含 MPC 与执行控制；
`composition.py`、`evaluation/optimization.py`、`evaluation/native_planners.py` 和任务环境
分别掌握方法选择、控制构造和步进顺序。下一版把这些知识集中到两个深模块。

决策方法从允许的信息与目标生成带时间和单位契约的轨迹或控制命令。
学习实现持有策略参数和记忆，优化实现持有预测模型、代价、约束、求解器与暖启动，
混合实现按声明顺序组合网络和求解器。PPO、APG、SHAC、D.VA 等更新算法继续归训练。

执行状态转移接收上述具名命令，装配所需的命令转换、控制链与前向动力学，
处理限幅、频率、延迟和控制记忆，并返回新物理状态、子步物理证据与执行诊断。
任务模块据物理证据判定到达、碰撞失败和超时。当前 P5 的共同命令层级是姿态角与总推力；
其他命令和机型使用明确兼容的原生组合。MPC 在控制理论中仍称控制器，平台仅按职责分槽位。

任务协议集中约束目标、时间、事件和评测规则；模块声明自身命令、状态、信息与导数能力。
装配层核对具体组合。新增论文任务协议的数值规则在其具名配方内维护。

## 导数配置方向

采纳用户提出的算法子配置方向，建议公开选择入口为 `algorithm.gradient`。
算法选择反传范围与具名规则，动力学、控制器、传感器或可微求解器实现提供对应导数能力。
同一个直接/代理规则的实现和能力声明各有单一来源，装配层检查算法选择能否被满足。

PPO 在网络上计算参数梯度；APG、SHAC、D.VA、LOTF 等可微展开方法额外声明环境梯度路径。
停止观测对状态的梯度仍允许训练编码器参数。LOTF 的代理规则作用于其声明的完整转移，
状态投影和控制执行次数随预设锁定。当前 `dynamics.backward` 与算法内停止梯度保持当前
运行语义；迁移的具体字段、规则身份和测试面在实施规格中冻结。

## 深模块与验收原则

删除测试：移除决策与执行模块后，方法记忆、命令契约和步进顺序会重新散回多个调用者。
该集中化提供修改的局部性，并让训练和评测从同一调用者接口获得完整执行能力。
真实替换点用神经策略与在线优化、Crazyflow 与 LOTF 等实际实现验证；原生 ROS 进程
保留进程适配，JAX 批量执行保留纯函数状态传递。

实施时从公开装配接口验证命令语义、单位、频率、重置、失败处置和一次且完整的控制执行；
直接导数对照实际前向的有限差分，代理导数对照其声明规则。
场景事件测试覆盖物理子步碰撞、真正终止、超时截断和末端观测。

## 仍待讨论的配置组织

场景与任务的职责分别定义；用户可通过一个环境预设组合使用。是否新增这层包装继续讨论。
传感器当前位于 `observation.sensor`，独立源码模块已经存在；提升为一级尚待决定。
训练目标可作为奖励和损失的总称，二者保留数学职责与唯一实现来源；最终配置路径待决定。
任务可配置多种观测或同次运行的多个接收者观测组；具体实现范围与比较协议待确认。
