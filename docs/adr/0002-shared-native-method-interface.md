# 原生算法共用宿主接口，适配器拥有算法与部署差异

状态：设计决定已确认；实现属于第一版阶段 B，协议字段随首批适配实现冻结。

用户要求后续 MIGHTY 等 C++ 算法沿用 SUPER／EGO 的接入方式。当前两种规划器已有标准输入输出上的 JSON 通信，但方法选择、ROS 启动和传感处理仍有专用分支；返回的当前参考也不能替代 MPC 所需的完整轨迹。

第一版统一宿主调用、能力声明、物理输出、时钟、回合状态和失败语义。每个方法提供适配器，负责原生输入、依赖、状态和输出转换；容器与本地进程使用相同通信合同。SUPER／EGO 保留固定 ROS 容器作为真实首批适配，去 ROS 核心抽取仍为后续工作。

新增方法应复用宿主闭环和评测逻辑，改动集中在适配器、配置与合同测试。不同方法仍可要求不同传感器或额外输入，必须显式声明来源；不因接口统一而声称可微、已完成内部模块抽取或已经实现 MIGHTY。

完成条件和实现顺序见[第一版规格](../release-plan.md#通用原生方法接口首版要求)。
