# 配置驱动的可组合组件架构

Drone Playground 采用**配置驱动的可组合组件架构**：通过实验配置选择职责明确、
契约兼容的模块实现，由装配层形成可执行闭环，并记录实际生效的组合。
模块命名统一使用 [领域术语](../CONTEXT.md)。

本页于 2026-09-28 核对本地 `31129a8` 及当时工作树；本轮交付范围为定义、设计文档和
Archify 架构图。文中的“现有”以读取到的配置和调用链为依据，“建议扩展”是后续设计。
并行进行的原生规划器运行环境迁移和场景更新各有自己的验证记录。

## 当前槽位清单

当前 `configs/config.yaml` 有六类闭环配置与四类训练配置，共十个一级配置组。
`experiment` 是组合预设；`evaluation` 和 `replay` 是现有内嵌运行配置。
传感器已有独立实现，配置入口为 `observation.sensor`；前向与反向选项位于 `dynamics` 内。

| 槽位 | 配置入口 | 当前实现或选项 | 职责与拥有的状态 |
|---|---|---|---|
| 策略（含轨迹规划） | `policy` | 神经姿态策略、感知导航策略、LOTF 状态策略、固定/随机参考、EGO、SUPER | 由观测和目标产生轨迹或命令；原生规划器拥有地图、求解状态与轨迹缓存 |
| 控制器 | `controller` | Crazyflow 姿态链、轨迹跟踪、LSY AttitudeMPC、SamplingMPC、LOTF 飞控 | 将方法输出转换成动力学命令；内部含跟踪、飞控与混控；拥有积分器和控制记忆 |
| 动力学 | `dynamics` | Crazyflow：`so_rpy`、`so_rpy_rotor`、`so_rpy_rotor_drag`、`first_principles`；LOTF 高保真/简化 | 前向推进机体与电机；保存原生物理状态 |
| 场景 | `scene` | 空场、LSY 赛道、LOTF 世界、静态/动态导航及固定目录 | 几何、障碍运动、外部作用；场景本身与方法内部地图分别管理 |
| 观测 | `observation` | 状态、状态＋参考、LOTF 状态、D435 历史、MID-360 历史 | 方法可见信息、采样、坐标、归一化及历史组织 |
| 任务 | `task` | 八字、随机样条、竞速、LOTF 悬停/跟踪、静态/动态导航 | 目标、时间、事件、重置、成功与失败判定 |
| 训练算法 | `algorithm` | PPO、APG、SHAC、D.VA、LOTF BPTT | 参数更新、展开时域、优化器、价值估计与算法缓冲 |
| 网络 | `network` | Brax 网络、LOTF 多层感知机、P5 深度/点集编码器 | 可训练表示、策略与价值网络、动作分布和初始化 |
| 训练目标 | `objective` | 跟踪奖励、导航奖励、LOTF 原任务目标 | 任务奖励和具名损失项；算法负责将其组合成自身更新目标 |
| 训练运行设置 | `training` | 种子、预算、并行数、设备、评估保存频率、恢复 | 一次训练的资源与生命周期 |

相应源码主要在 `policies/`、`controllers/`、`dynamics/`、`tasks/`、`learning/`。
`composition.py` 负责配置解析、构造和组合校验；`contracts.py` 记录命令定义。
当前源码包含针对导航、LOTF、跟踪/竞速的专用装配分支，支持范围由这些分支和测试决定。

### 子槽位与内部组合

| 子槽位 | 当前归属 | 当前实现 | 设计规则 |
|---|---|---|---|
| 传感测量 | `observation.sensor`；`tasks/sensors/` | D435 解析深度、MID-360 非重复扫描图案 | 负责测量几何、内外参、频率、有效性与坐标；历史数组、采样序号由环境状态保存 |
| 特征编码与时序处理 | `network` | 深度卷积、逐点编码及池化、历史特征拼接 | 编码器参数随策略训练；未来 PointNet/GRU 在此扩展 |
| 前向状态转移 | `dynamics.forward` 配合控制器 | Crazyflow 四模型、LOTF 原生执行 | 产生实际执行状态；控制器内环按预设执行一次 |
| 状态转移导数 | `dynamics.backward` | Crazyflow 直接导数、LOTF 解析代理/直接导数 | 独立记录导数作用的状态、动作和转移范围 |
| 观测导数边界 | 当前在 `learning/dva.py` | 整体观测停止状态梯度 | 当前实现写在算法内部；独立可配置的观测导数子选项属于建议扩展 |
| 优化预测模型 | `controller.prediction` 或原生规划器内部 | MPC 的声明模型；EGO/SUPER 内部模型 | 用于求解预测，与执行动力学分别记录 |
| 轨迹跟踪与飞控 | `controller` 内部 | 参考跟踪、姿态内环、混控 | 对外保留一个控制器预设；内部按实际命令层级组合 |

本设计保留十个一级配置组。新增可替换实现优先进入已有槽位；具有真实独立组合需求的子槽位，
再按需要提升配置层级。此前讨论中的一级 `sensor`、`gradient` 属于可选设计，当前文档采用
层级化子槽位方案，延续 [ADR-0004](adr/0004-composable-flight.md) 的简化配置约定。

## 双通道执行与汇合条件

学习式：传感测量 → 观测表示 → 已训练网络 → 策略命令映射。
优化式：传感测量与状态 → 方法内部地图/预测 → 在线规划或优化控制 → 所需命令转换。
两者在兼容的命令契约处进入共享执行层。

当前 P5 的具体汇合点是 `attitude_thrust`：滚转角、俯仰角、偏航角、总推力。
前三个量的单位均为弧度，推力为牛顿；偏航量是角度。
学习策略通过 `AttitudeControl.physical_action()` 映射动作；EGO/SUPER 的轨迹经过
`TrajectoryTracking.command()` 生成同一层级的命令。后续通过导航任务的姿态控制与
Crazyflow 状态推进执行。对应实现为 `controllers/crazyflow.py`、`controllers/trajectory.py`、
`evaluation/native_planners.py` 和 `tasks/navigation.py`。

现有 AttitudeMPC 与 SamplingMPC 属于优化式控制器，配置位置为 `controller`，其上游是固定
或任务参考。EGO/SUPER 属于在线轨迹规划器，配置位置为 `policy`。图中的优化式通道以 P5
原生规划器为具体实例；模块归属同时由其输入输出职责决定。

LOTF 使用“推力＋机体系角速度”及其原生飞控；未来加速度策略使用另一种命令契约。
这类组合先经过对应控制器，再在适配后的执行层或共同外部评测协议上比较。
共享层是兼容性关系；每个实验分别实例化自己的运行状态。

当前命令字典还包括电机转速与轨迹类型。字典声明、实际消费者支持和经过验证的组合，
分别构成三个层次的证据。轨迹声明目前较粗，原生 P5 实际需要位置、速度、加速度、偏航
和时间有效性；更精确的轨迹契约列入后续装配深化工作。

## 训练侧与模型用途

PPO、D.VA 等是训练算法；执行时使用其生成的策略参数。学习率、参数优化器与小批量属于
`algorithm`。在线轨迹求解器和暖启动属于持有该优化问题的规划器或控制器。
可微优化策略将网络与求解器组合在策略内部，并另外声明导数能力；本页预留此概念位置。

前向模型产生执行状态；预测模型服务优化求解；反向模型提供训练导数。三种用途分别记录，
可使用相同方程，也可使用不同精度和状态布局。Crazyflow 当前导航分支只接受直接导数。
LOTF 的代理导数覆盖作者定义的控制/物理转移，采用具名状态投影。

D.VA 当前在策略入口停止整个观测对状态的梯度；感知编码器的参数仍然训练。
控制与动力学对动作的导数、冻结目标价值网络对末端物理状态的导数，继续用于短窗口更新。
传感器射线关于位姿的导数能力，需要单独验证和登记。

点云论文、DiffPhysDrone 式导数衰减和完整可微传感器分别作为后续具名配方。
复现 DiffPhysDrone 时应按上游实际反向核对齐位置/速度等具体分量；“整体状态雅可比乘同一系数”
应登记为平台消融规则。论文式梯度与源码式梯度需保留各自来源和验证目标。

## 槽位管理的契约

每个可替换位置需要说明六件事：输入输出及单位/坐标、状态所有权、调用顺序与频率、
有效时间与失败行为、可见信息、导数能力。配置完成后，装配层验证相邻契约并固定实现身份。

方法状态含循环网络记忆、地图、暖启动；控制状态含积分器、上一动作和延迟队列；
物理状态含机体与电机；环境状态含传感器历史、扫描相位与场景时钟；训练状态含参数、
优化器和随机数。各模块保存自己的原生表示，恢复流程统一核查依赖和时间语义。

导数验证区分直接导数与代理规则：前者对照同一前向的有限差分，后者对照其声明的反向模型。
观测导数、动作导数和参数导数分开测试。测试从调用者使用的装配接口进入，并覆盖两种以上
真实实现的替换行为。

## 单一领域与外部适配

领域驱动设计在本项目的应用为：维护统一术语、明确模型用途、为外部原生实现设置翻译接口。
学习式与优化式两列共享无人机实验的领域语言；它们是策略类别。
平台任务模型、Crazyflow/LOTF 原生状态和 ROS 规划器模型之间存在不同语义，
由适配模块集中处理坐标、命令、时间、进程生命周期和失败状态。

EGO/SUPER 的地图与求解器保留在原生工作进程；平台提供传感测量、里程计、目标和时钟，
接收有效轨迹。MuJoCo 用于当前回放展示与几何核对；实际推进由配置选择的动力学负责。
Isaac Lab 的管理器式工作流用于职责划分参考；项目实现继续沿用 Hydra 与 JAX 的装配和函数式步进。

## 比较、记录与恢复

控制变量比较需要同时核对场景、目标、可见信息、采样预算、时延、控制器、动力学和评测协议。
完整方法比较允许保留方法原生链，并在报告中列出这些差异。
当前 P5 学习组读取压缩历史，EGO/SUPER 读取原始深度或点云；该矩阵属于完整方法比较。

`evaluation/execution.py` 组织冻结策略/优化器评测，`runs/` 保存解析配置、代码和依赖身份、
种子、检查点、逐回合结果和 RScope 回放。开发集负责选模，留出集用于冻结后评价。
恢复能力按算法与已有证据登记；PPO 参数暖启动与完整训练状态恢复分别记录。

下一项建议深化的是完整状态转移的装配接口：集中处理控制器选择、命令契约与物理推进，
并保留 JAX 批量执行和 ROS 原生工作进程各自的真实适配方式。具体候选、收益及实施边界见
[设计依据](research/composable-slot-design.md)；本轮以文档和图示表达该设计。
